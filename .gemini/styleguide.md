# Book Store — Code Review Style Guide

This guide steers Gemini Code Assist when it reviews pull requests in this repository. It is derived from
`.specify/memory/constitution.md` (v1.0.0). Where the two disagree, the constitution wins.

## How to rate severity

| Severity | Use it when |
|---|---|
| CRITICAL | A NON-NEGOTIABLE principle is broken (IV Money Is Decimal, V Test-Gated Delivery) or a secret is exposed |
| HIGH | Any other constitution principle is broken, or the change is a security risk (injection, PII in logs, CORS opened) |
| MEDIUM | Correctness or maintainability issues that a reasonable reviewer would block on |
| LOW | Naming, formatting, readability |

Always name the principle in the comment, e.g. **"Constitution IV"**, and include a committable suggestion when the
fix is local.

## Rules mapped from the constitution

### I — Specification before code
- A change to `src/` or `web/src/` with no matching task in `specs/*/tasks.md` → HIGH ("untraced change").
- New endpoints or pages not described in a `spec.md` → HIGH.

### II — Contract-first APIs
- Routes must start with `/api/v1/`. Unversioned routes → HIGH.
- Responses must be DTO records from `<Feature>Contracts.cs`; returning EF entities or anonymous objects → HIGH.
- Errors must be Problem Details (`Problem(...)`, `ValidationProblem(...)` or a domain exception) → MEDIUM otherwise.
- An endpoint that is not in `specs/*/contracts/*.openapi.yaml` → HIGH.

### III — Layered backend
- Controllers must not reference `BookStoreDbContext` → HIGH.
- `FromSqlRaw`/`ExecuteSqlRaw` with string interpolation or concatenation → CRITICAL (injection).
- `.ToList()` before `.Where(...)` on a DbSet (loads the whole table) → MEDIUM.
- Missing `CancellationToken` on async controller actions and service methods → LOW.

### IV — Money is decimal
- `double` or `float` for any price, amount, total, subtotal, average order value or discount → CRITICAL.
- Monetary arithmetic in React/TypeScript → HIGH (the client formats with `formatInr` only).

### V — Test-gated delivery
- New or changed behaviour without an xUnit test → CRITICAL.
- A new user-facing page or journey without a Playwright test → CRITICAL.
- Skipped, deleted or weakened tests → CRITICAL.

### VI — Secrets stay out
- Credentials, keys or connection-string passwords outside `appsettings.Development.json` → CRITICAL.
- Personal data (email addresses) written to logs or the console → HIGH.
- `AllowAnyOrigin()` in CORS → HIGH.

### VII — Simplicity
- New NuGet/npm dependency without a `research.md` entry → MEDIUM.
- Generic repository / unit-of-work wrappers over EF Core → MEDIUM.

## C# style

- File-scoped namespaces, primary constructors for DI, `sealed` by default.
- `ILogger<T>` with message templates; never `Console.WriteLine`.
- Nullable reference types enabled; no `!` suppression without a comment explaining why it is safe.

## TypeScript / React style

- `strict` TypeScript, no `any`.
- Every view handles loading, error and empty states.
- `data-testid` on every element a test touches; stable `key` props.

## What NOT to comment on

- Formatting that `dotnet format` or the TypeScript compiler would accept.
- Files under `.specify/` (generated by Spec Kit) and `web/package-lock.json`.
- Workflow files under `.github/workflows/` are outside the review agent's scope — humans review those.
